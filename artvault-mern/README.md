# ArtVault

Gallery, private artwork Vault, and exhibit management using React/Vite,
Express/Node, MongoDB/Mongoose, and Supabase authentication.

## Local setup

Use Node.js 22+, npm, and a MongoDB connection. In `server`, run `npm install`,
copy `.env.example` to `.env`, and configure the database, a strong JWT secret,
Supabase server settings, allowed frontend origin, and email transport.
Run `npm run dev`. Use `npm.cmd` on Windows when PowerShell blocks `npm.ps1`.

In `client`, run `npm install`, copy `.env.example` to `.env`, and configure the
Supabase URL/publishable key. Run `npm run dev`; requests from localhost use
Vite's `/api` proxy to the local backend. The API health endpoint is `/api/health`.
`npm run seed` creates demo data: use a separate demo database, not production.
Never commit real `.env` files or put server API keys in `VITE_*` variables.

## Implemented workflows

- Public gallery with server-side title/category/artist search, category filters,
  Others/custom artwork labels, and 24-item pagination.
- Artist profiles, required ownership declaration/proof, public/private artworks,
  thumbnails generated by the server, and owner-only visibility changes.
- Local NSFWJS sexual-content screening before artwork/proof storage. No API key
  or billing is required for this step. See `server/CONTENT-SCREENING.md`.
- Optional Cloud Vision online matching and Gemini proof assessment. Matches,
  unavailable checks, and uncertain proof await manual review. No online match
  plus credible creation evidence permits automatic approval. These are routing
  signals, not proof of copyright ownership. Cloud Vision needs billing setup.
- Main-admin ownership decisions; sub-admin monitoring; artist exhibit submissions
  and administrator selection; scheduled exhibit lifecycle notices.
- Likes, in-app/email notifications, activity logs, archives and artist recovery.
- Public privacy notice at `/privacy` describes provider processing and deletion
  limitations. Account deletion does not automatically erase every archive.
- Reviewer-only `/analytics`: date-filtered workload, upload trends, public category
  distribution, exhibit decision rates, and CSV export. Private images, proof,
  email addresses, and private category labels are excluded from reporting.
- Supabase authenticator enrollment in Settings and `/mfa` sign-in challenge.
  Backend MFA checks apply to accounts with verified factors. MFA is opt-in,
  not an institution-wide enrollment requirement. Legacy JWTs cannot authenticate
  accounts already linked to Supabase.
- One-time backup security codes in Security work independently of authenticator
  enrollment. Users may enable either method or both; either verifies sign-in.
  Generating/replacing/disabling codes requires a purpose-bound
  eight-digit email OTP with 10-minute expiry, one-minute resend cooldown and five
  attempts. Ten random codes are shown once/downloadable and stored only as
  account-bound HMAC digests. Each backup code verifies the current provider
  session for ArtVault API access for 15 minutes; it does not upgrade Supabase
  to aal2 or authorize provider-side authenticator removal. Invalid recovery
  attempts are limited; expired recovery sessions require fresh verification.
  Keep `JWT_SECRET` stable: rotating it invalidates stored backup-code digests.
- Logout revokes the current access token in MongoDB (hash only, with expiry/TTL).
  The browser also signs out of Supabase. A failed/offline logout request cannot
  guarantee server revocation; existing tokens otherwise expire normally.

## Deployment

Deploy the `server` folder on the backend host with `npm ci` and `npm start`.
Set `NODE_ENV=production`, a JWT secret of at least 32 characters, and actual
server variables from `server/.env.example`. Use `JWT_EXPIRES_IN=30m` for legacy
tokens. Existing deployment values are not overwritten by changing the template.
The database connection creates the revocation TTL index and entry reporting index.

Deploy the `client` folder with `npm ci` and `npm run build`; output is `dist`.
Set `VITE_API_URL` to the HTTPS backend URL ending in `/api` and configure the
public Supabase variables. A valid deployment URL is honored; localhost and
malformed multi-URL values fall back to the existing Railway URL. Vite variables
are embedded at build time, so changing them requires a frontend rebuild.
Set server `CLIENT_ORIGIN` to the deployed frontend origin. Provide SPA route
rewrites on the frontend host. Do not enable prototype authentication in production;
it is now limited to Vite development without Supabase.

For MFA, enable TOTP enrollment/verification in Supabase Authentication settings,
then enroll a test account from ArtVault Settings. Verify that an ordinary
password-only token gets `403 MFA_REQUIRED`, a valid authenticator challenge grants
access, and logout rejects replay of the old token. Do this in staging first.
Lost-factor recovery requires a trusted deployment operator using Supabase's
administration tools; never remove another user's factor based on an unverified request.
Reference: https://supabase.com/docs/guides/auth/auth-mfa/totp

## Reporting definitions

Analytics uses Philippine calendar-day boundaries, defaulting to the last 30 days
and limiting requests to 366 days. Data is generated from current database records
created in the selected period, not immutable historical snapshots. Removed records
are excluded. Active artists means distinct artwork uploaders, not login activity.
Pending age is calculated from submission time. Categories count each label once
per approved public artwork and show the top 25; multi-category works appear in
multiple buckets. Exhibit approval rate is approved / (approved + denied), with
no percentage when no decisions exist. Days without uploads are represented as zero.

## Verification

Run `npm test` from `server` and `npm run build` from `client`. GitHub Actions
runs both on pushes and pull requests. Backend tests use mock records/provider
responses, plus a real bundled-model offline inference smoke test. They do not
substitute for real database, SMTP, Supabase MFA, or deployed browser acceptance tests.
See `DEFENSE-READINESS.md` for staging checks and remaining work.

## Architectural tradeoffs

MongoDB documents hold flexible artwork metadata and embedded Base64 images.
References connect artists, artworks, submissions, and exhibits. Indexes support
owner/date queries and reporting; media is projected out of analytics pipelines.
Local classification runs in a separate worker with bounded queue and timeout.

Base64 images increase database size and transfer cost; move media to private
object storage with authorized/signed access as volume grows. Regex substring
search and skip-based pagination are suitable for a modest gallery but should be
replaced by indexed search/cursor pagination at scale. Name search currently
limits matching artist IDs to 200. Daily reporting is capped to control query work.

Current bearer/Supabase session tokens still use browser storage. HttpOnly/Secure
cookie sessions, CSRF protection, refresh/revocation strategy, and cross-site
deployment behavior require a coordinated authentication migration. Client idle
logout is not proof of server-enforced inactivity expiry. Do not claim the full
security rubric is satisfied until these are implemented and verified.
